# 帧率统计任务生成方案

> 关联需求文档：`帧率统计任务.md`
> 输入材料：`帧率统计模板.xlsx`、`20260901112214/`（Raptor Pro 走 WIFI 开流 1000 帧的实机日志）

## 1. 文档目的

在 Jens PC 自动化测试平台中新增一类「帧率统计」任务生成：

1. 平台自动按规则选出某模组需要统计的扫描模式；
2. 每个模式按「预览 → 扫描至 1000 帧 → 停止」执行开流测试；
3. 运行结束后从 CrealityScan 日志提取预览帧率、扫描最大/最小帧率、稳定帧率；
4. 把系统信息、软件版本、固件版本、模式帧率汇总写入 `帧率统计模板.xlsx` 风格的 Excel。

本文档只描述方案与验收口径，不包含最终代码；最终实现前需与测试负责人确认第 9 节的开放问题。

## 2. 需求确认（来自 `帧率统计任务.md`）

- 各模组都有统计帧率的测试需求，平台需要新增一个任务生成入口。
- 需要统计的模式（按模组实际存在与否取舍）：
  1. 散斑的大/中/小物体；
  2. 人脸纹理高精度、人体纹理高精度（模组没有“高精度”后缀时退化为“纹理”）；
  3. 三种激光线模式：平行线、单线、交叉（没有的模组不带；只有两种的带两种）；
  4. 无标记点模式（模组存在才带）。
- 扫描帧数固定 1000 帧。
- 需要统计三个帧率数值：**预览帧率**、**扫描时最大帧率 - 扫描时最小帧率**、**稳定帧率（1000 帧左右的平均帧率）**。
- 生成到 G 列还是 H 列，取决于用户选择的是 **WIFI** 还是 **USB** 连接：
  - WIFI → 写入 G 列（含 G1 表头）；
  - USB → 写入 H 列（含 H1 表头）。
- G1/H1 表头信息模板：
  - G1（WIFI）：`模组名 + 连接方式 + 固件版本： + wifi手柄版本：`
  - H1（USB）：`模组名 + 连接方式 + 固件版本：`
- 软件版本取软件日志目录下 `app.log` 第一行：`[…] [Debug] Development version: 1.12.11`。
- 电脑、系统版本、wifi5/6、电脑型号、内存由工具获取。

G3/H3 每一行格式为：

### 3.2 样本日志（`20260901112214/`）分析结论

该样本为 **Raptor Pro 走 WIFI**、单模式（线激光）开流 1000 帧：

- `system_info.txt`：CPU / 内存 / GPU / OS 等系统信息；
- `device_info.json`：模组 `Creality Raptor Pro`、SN、固件版本 `1.4.9`；
- `app.log` 第一行：`Development version: 1.12.11`（软件版本）；
- `app.log` 中 `SCAN_BRIDGE / CR_Scan_Pocket_sys` 版本 `1.3.1`（即 wifi 手柄版本）；
- `scan_log_2026*.txt` 时间轴：
  - `obscan_scan_preview` ≈ `11:23:39.56`（预览开始）；
  - `obscan_scan_start` ≈ `11:23:46.85`（扫描开始，随后 `frame 1`）；
  - `frame 1000` ≈ `11:24:19.78`；
  - `OB_SCAN_MESSAGE_ID_SCANNING_STOP_SUCCESS` ≈ `11:24:23.12`；
- `ScannerStreamSDK.log` 中 `Pipeline streaming... frameset output rate=40.62fps` 等采样点约每 5 秒一条，共 8 条，其中预览阶段 1 条、扫描阶段 7 条。

**结论：帧率的可靠数据源是 `ScannerStreamSDK.log` 的 `frameset output rate`（SDK 帧集输出速率），而不是 `scan_log` 的 `frame N` 计数（后者按秒分桶约 30fps，与模板范例 40fps 量级不符）。**

## 4. 任务生成设计

### 4.1 新增任务类型：帧率统计

在现有“开流 / 后处理”之外新增第三类任务类型：

- 名称：`帧率统计`（内部常量 `TASK_KIND_FPS_STAT = "帧率统计"`）；
- 步骤编排 = 现有“开流”逻辑（不含融合/封装/贴图），因为只统计帧率，不需要后处理；
- 目标帧数固定 `1000`（界面可改但默认 1000）；
- 连接方式仅在有 USB/Wi-Fi 变体的模组上可选，无连接变体的模组（如 Otter/Ferret/Raptor）默认不带连接后缀。

### 4.2 模式选择规则（业务模式 → preset key）

生成任务时不再让用户手工多选全部 preset，而是按业务规则自动挑选并固定顺序。规则（大小写不敏感，优先匹配 `key`，其次 `name`/`aliases`）：

| 顺序 | 业务模式 | preset 匹配规则 | 备注 |
|---|---|---|---|
| 1 | 平行线 | `<mod>.line_laser.point_cloud.parallel` | 没有则跳过 |
| 2 | 单线 | `<mod>.line_laser.point_cloud.single` | 没有则跳过 |
| 3 | 交叉 | `<mod>.line_laser.point_cloud.cross` | 没有则跳过 |
| 4 | 无标记点 | key/alias 含 `no_marker` / `无标记点` / `无标志点` 的 line_laser preset | 仅 USB；模组没有则跳过 |
| 5 | 大物体 | `<mod>.speckle.*.large.geometry*` | 默认取几何；见 Q2 |
| 6 | 中物体 | `<mod>.speckle.*.medium.geometry*` | 默认取几何；见 Q2 |
| 7 | 小物体 | `<mod>.speckle.*.small.geometry*` | 默认取几何；见 Q2 |
| 8 | 人脸 | `face.texture.high_precision`，退化 `face.texture` | 优先高精度 |
| 9 | 人体 | `body.texture.high_precision`，退化 `body.texture` | 优先高精度 |

输出到 Excel 的“模式名”使用短名：`平行线 / 单线 / 交叉 / 无标志点 / 大物体 / 中物体 / 小物体 / 人脸 / 人体`（与模板范例一致；`无标记点`在模板中写作`无标志点`，见 Q3）。

关键取舍：

- **无标记点仅 USB**：各模组 `line_laser.no_marker*` preset 的 `connections` 基本是 `["usb"]`。模板范例中 G3（WIFI）没有“无标志点”、H3（USB）有，佐证了这一点。生成规则：连接为 WIFI 时跳过无标记点，连接为 USB 时才带。
- **人脸/人体退化规则**：优先 `…texture.high_precision`；模组没有高精度后缀（如 Raptor Pro 只有 `face.texture`/`body.texture`）时退化为 `…texture`。
- **激光线按存在性取舍**：如 Raptor Pro 只有 平行线 + 交叉（无单线），则只带两种，符合需求描述。

### 4.3 生成步骤编排（以非 Pika 模组为例）

每个模式重复：

```text
1. crealityscan.configure_scan_params_<mod>（params.preset = 该模式 preset key）
2. crealityscan.preview_scan（预览）
3. crealityscan.scan_until_frames_then_stop（params.target_frames = 1000）
```

整体编排：

```text
common.activate_window（如该模组需要）
crealityscan.create_project（新建项目）
（对每个模式：configure_scan_params → preview_scan → scan_until_frames_then_stop）
（模式之间：crealityscan.create_scan 新建扫描）
```

Pika 等需要稳定性等待的模组，沿用 `task_generator.py` 现有 `pika_waits` 处理（关键节点自动等待）。

### 4.4 生成入口（UI）

在现有“新建任务”向导中：

- 任务类型卡片新增“帧率统计”单选（`开流 / 后处理 / 帧率统计`）；
- 选择“帧率统计”后，模式列表自动按第 4.2 节规则预勾选并固定顺序，用户可取消个别模式；
- 目标帧数默认 1000；
- 摘要区显示：将生成的模式清单、预计步骤数、连接方式、是否含无标记点（仅 USB）。

## 5. 帧率统计：数据来源与提取算法

### 5.1 数据源

| 指标 | 来源文件 | 匹配关键字 |
|---|---|---|
| 预览/扫描阶段切分 | `scan_log_*.txt`（或 app.log） | `obscan_scan_preview`（预览开始）、`obscan_scan_start`（扫描开始）、`OB_SCAN_MESSAGE_ID_SCANNING_STOP_SUCCESS`（停止成功） |
| 帧率采样 | `ScannerStreamSDK.log` | `Pipeline streaming... frameset output rate=<数值>fps` |
| 软件版本 | `app.log` 第 1 行 | `Development version: <版本>` |
| 固件版本 | `device_info.json` | `firmwareVersion`（或 app.log 中当前设备固件） |
| wifi 手柄版本 | `app.log` | `SCAN_BRIDGE` / `CR_Scan_Pocket_sys` 的 `version = <版本>` |
| 系统信息 | `system_info.txt` | CPU / Memory / GPU / GPU Memory / OS |
| wifi5/6 | 运行环境（`netsh wlan show interfaces` 的 Radio type） | 802.11ax → wifi6；802.11ac → wifi5 |

### 5.2 提取算法（分阶段）

1. 解析 `scan_log_*` 得到三个时间戳：`t_preview`（obscan_scan_preview）、`t_scan`（obscan_scan_start）、`t_stop`（SCANNING_STOP_SUCCESS）。
2. 解析 `ScannerStreamSDK.log` 中所有 `frameset output rate=<v>fps` 采样点（含时间戳）。
3. 按时间切分：
   - 预览采样：`t_preview ≤ t < t_scan`
   - 扫描采样：`t_scan ≤ t ≤ t_stop`
4. 计算：
   - `预览帧率 = round(mean(预览采样值))`
   - `扫描最大帧率 = round(max(扫描采样值))`、`扫描最小帧率 = round(min(扫描采样值))`
   - `稳定帧率 = round(mean(扫描采样值))`（约等于 1000 帧期间的平均帧率）
5. 输出一行：`模式名：预览帧率；扫描最小-扫描最大；稳定帧率`

### 5.3 样本实测（用于验证算法）

用 `20260901112214/` 样本验证：

- 预览采样（1 条）：`40.62` → 预览帧率 `41`
- 扫描采样（7 条）：`40.05, 40.18, 39.90, 40.11, 39.78, 38.94, 40.75`
  - 最小 `38.94` → `39`
  - 最大 `40.75` → `41`
  - 平均 `39.96` → 稳定帧率 `40`
- 结果行：`线激光（样本）：41；39-41；40`

该量级（~40fps）与模板 WIFI 范例（39~40）一致，证明数据源正确。

> 边界：若某阶段没有采样（例如预览阶段过短没有 frameset 采样点），该阶段值记为空并提示，不硬算；若一次运行含多次 pipeline 会话，按 4.4 节的任务步骤与 SDK 会话做时间匹配（复用 `jens_runner_entry.py::_attach_sdk_fps_stats` 的匹配思路），一一对应。

### 5.4 与现有代码的关系

- 现有 `engine/logs.py::extract_sdk_fps_sessions` 只能给出整个 pipeline 会话的 avg/peak/min，未区分预览/扫描阶段。**需要新增** `extract_fps_metrics_by_phase(logs_root) -> {preview_avg, scan_max, scan_min, scan_avg, …}`。
- 现有 `engine/scan_fps_xlsx.py::write_scan_fps_workbook` 输出的是“每次扫描一行”的流水表，**不是**模板风格。**需要新增** `write_fps_stat_workbook(...)` 按模板写入 A1:H3。

## 6. Excel 输出规范（严格按模板）

- Sheet 名 `Sheet1`，表头 A1:H1 与模板一致；
- 字体 `Microsoft YaHei 14`，表头加粗居中；G3/H3 左对齐、自动换行、多行文本；
- A2:A3 合并，写入软件版本 `win<版本>`（如 `win1.12.11`）；
- B3 电脑简称（如 `5060笔记本`，取 GPU 型号短名）；
- C3 系统版本（`system_info.txt` 的 OS 行，可格式化为 `Windows 11 专业版\n<版本号>\n<build>`，见 Q4）；
- D3 wifi5/6（运行环境检测结果；非 WIFI 连接留空）；
- E3 电脑型号明细（CPU / CPU Cores / Memory / GPU / GPU Memory，按 `\n` 换行）；
- F3 内存（如 `32g`，由 MB 换算取整）；
- G1（WIFI）：`<模组名> WIFI（固件版本：<固件>+wifi ：<手柄版本>）`
- H1（USB）：`<模组名>(USB) 固件版本：<固件>`
- G3 或 H3：按第 5.2 节逐模式一行，按第 4.2 节顺序，`\n` 连接。

生成哪一列取决于用户选择的连接：WIFI → G，USB → H；另一列保留为空（不覆盖已有内容，便于同一文件同时积累 WIFI 与 USB 两轮数据）。

## 9. 开放问题与假设（已确认）

> 已由测试负责人确认，结论见下方【确认】；本文档描述的方案已按此落地实现。

- **Q1** 扫描区间书写顺序：需求原文“最大-最小” vs 模板范例“最小-最大（39-40）”。
  - 【确认】按模板，**最小到最大**（升序）。
- **Q2** 散斑大/中/小物体默认 preset。
  - 【确认】不需要纹理/标志点，**大中小物体取几何（geometry）**即可。
- **Q3** 模式短名：模板 USB 范例写作“无标志点”。
  - 【确认】**统一为“无标记点”**（Excel 输出统一使用“无标记点”，全角冒号）。
- **Q4** 系统版本（C3）展示格式。
  - 【确认】**自动补全专业版/版本名**（如 `Windows 11 专业版` + `23H2` + `22631`；未收录的 build 只补“专业版”）。
- **Q5** 四舍五入规则。
  - 【确认】**四舍五入**（实现为 half-up：`floor(x + 0.5)`）。
- **Q6** 帧率采样密度（SDK 约每 5 秒一条，预览阶段可能仅 1 条）。
  - 【确认】可以接受。
- **Q7** 激光线缺项是否占位。
  - 【确认】**跳过**（不占位）。
