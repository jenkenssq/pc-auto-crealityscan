# 压测模式 使用说明

> 平台内用于对 CrealityScan 执行“同一任务反复 N 轮”的稳定性压测。
> 每轮独立归档；遇到失败/卡死自动**强杀进程 → 重开软件 → 处理“软件意外退出”
> 上报弹窗（点取消）→ 进入下一轮**；结束生成 `压测汇总.json/.html` 并邮件通知。

---

## 1. 进入方式

### 1.1 界面（推荐）
1. 启动主平台。
2. 顶部工具栏点击 **压测模式** 按钮。
3. 弹窗中：
   - **压测任务（单选）**：从 `tasks/` 中选择一个已有任务（如
     `Raptor Pro无标志点50次后处理压测.json`）；
   - **CrealityScan.exe**：选择软件路径（首次选择后自动记忆，下次带出）；
   - **执行次数**：1~100000；
   - 点击 **开始**。
4. 状态栏显示 `压测模式：共 N 轮，失败/卡死自动杀进程重开。`
5. 中途可用现有 **停止** 按钮/F4 停止：**当前轮会完整跑完**（不打断），
   该轮结束后不再启动下一轮；若当前轮很长（整轮扫描+后处理），等待属正常现象。
   停止后仍会生成 `压测汇总.json/.html`（标记为“已停止”），已完成的轮次可查看。

### 1.2 命令行
```bash
# 压测编排（主进程）
python platform_app.py --stress-run \
  --case "tasks/Raptor Pro无标志点50次后处理压测.json" \
  --exe "C:/Program Files/Creality/CrealityScan.exe" \
  --rounds 50

# 可选参数
--freeze-timeout 180   # 卡死判定静默秒数（默认 180）
--launch-timeout 120   # 启动/重开等待秒数（默认 120）
--popup-timeout  40    # 上报弹窗处理秒数（默认 40）
# --stop-file <path>   # 内部用：GUI 停止时写入该文件实现优雅停止（一般无需手动指定）

# 单轮执行（由编排进程内部调用，一般无需手动使用）
python platform_app.py --stress-round --case <task.json> --round-dir <round_dir>
```

---

## 2. 一轮任务的定义
- 选中任务完整跑一遍 = 1 轮（B1-a）。
- 轮次末尾由执行器自动补一次 `return_home`，任务 JSON 不内嵌（保持现有约定）。
- 一轮内某个模式失败 → 该轮整体终止（B4-b），直接进入下一轮。

---

## 3. 失败 / 卡死处理

| 情形 | 处理 |
|------|------|
| 普通步骤失败（非卡死） | 本轮记失败（截图+日志+报告）→ 强杀进程 → 重开 → 下一轮（B3-a） |
| 软件卡死 | 日志无新行 + 无心跳静默超 `--freeze-timeout`（默认 180s）→ 本轮记“卡死”→ 强杀进程树 → 重开 → 下一轮（C4-c / C5-a） |
| “软件意外退出”上报弹窗 | 点击 **取消**（pywinauto 按钮“取消/Cancel”优先；Airtest 模板 `jens_platform/stress/templates/cancel_btn.png` 兜底）；找不到则截图留证 |
| CrealityScan 启动失败 | 该轮记失败，继续尝试下一轮 |

> 说明：压测模式**每轮最多恢复 1 次**——即失败/卡死后杀进程重开，重开后直接跑下一轮
> 而不是重跑本轮；若重开后仍无法启动，本轮按失败计并继续。

---

## 4. 产物结构

```
artifacts/
└── <任务名>_压测_<时间戳>/
    ├── 压测汇总.json          # 机器可读汇总
    ├── 压测汇总.html          # 人读汇总报告
    ├── round01/
    │   ├── result.json        # 单轮结果
    │   ├── report.html        # 单轮报告
    │   ├── *.png              # 截图
    │   ├── <日志副本>
    │   └── recovery/          # 失败/卡死后的恢复截图等
    ├── round02/
    └── ...
```

### 汇总字段（`压测汇总.json`）
- 顶层：`case_name`、`exe_path`、`total_rounds`、`started_at`、`finished_at`、
  `duration_sec`、`pass_rate`、`counts{passed,failed,frozen,skipped}`、
  `stopped`、`status`（passed/failed/stopped）、`rounds[]`。
- 每轮：`round_index`、`status`（passed/failed/frozen/skipped/stopped）、
  `reason`、`started_at`、`finished_at`、`duration_sec`、`round_dir`、
  `report_path`、`error`。

### 统计口径
通过率 = 通过 /（通过 + 失败 + 卡死）× 100%（跳过与停止不计入分母）。

---

## 5. 通知
压测整体结束后，若配置了 SMTP（`.env` 中 `SMTP_*`），会发送一封汇总邮件：
- 正文：任务名、总轮次、通过/失败/卡死、通过率、整体状态；
- 附件：`压测汇总.html`。

---

## 6. 常用默认值（当前固定，后续可开放）
| 参数 | 默认 | 说明 |
|------|------|------|
| 卡死静默超时 | 180s | 日志 + 心跳同时静默超时才算卡死 |
| 启动/重开等待 | 120s | 等待 CrealityScan 主窗口出现 |
| 弹窗处理等待 | 40s | 等待“软件意外退出”上报弹窗出现并点取消 |
| 每轮最大恢复 | 1 次 | 达到上限后本轮按失败计，进入下一轮 |

---

## 7. 验收基准
- 以 `tasks/Raptor Pro无标志点50次后处理压测.json`（手工 50 轮）为对拍基准：
  轮次划分、产物归档、失败/卡死分类、汇总统计口径应与手工 JSON 对齐。
- 对拍方式：手工 50 轮 JSON 是“展开版”（400 步 = 50 轮 × 每轮 8 步，含内嵌
  `return_home`）。压测模式是“循环版”，因此建议从该 JSON 提取**单轮版**任务
  （第 1 轮 8 步去掉末尾 `return_home`，因执行器会自动补），然后用压测模式
  以 **rounds=50** 运行，得到的 50 个 `round01…round50` 即与手工 JSON 的
  50 轮结构一一对拍。
