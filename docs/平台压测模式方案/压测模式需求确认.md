# 压测模式 需求确认清单

> 背景：`压测模式生成方案.md` 已明确目标——平台开设“压测模式”，切换后选择
> CrealityScan.exe 路径 + 执行次数；遇到软件卡死时截图、保存日志、强杀进程、
> 重开软件、处理日志上报弹窗后继续任务。
> 本文档列出落地前必须对齐的细节，请按编号逐条回复。每条都给出推荐默认值，
> 认可直接回“按推荐”，不同意请给出你的答案。

---

## A. 形态与入口

### A1. 压测模式的实现形态
压测 50 次以上，有两种做法：
- **A1-a（推荐）**：不展开巨型 JSON。在**执行器/调度层**做“循环 N 次 + 异常恢复”，
  每轮内部仍用正常 Step 流程；一轮=一次完整任务（新建项目→各模式扫描→后处理）。
- **A1-b**：沿用现在的手工方式，把任务展开成 N 轮 × 每轮步骤的单个大 JSON
  （如现有 `tasks/Raptor Pro无标志点50次后处理压测.json`，400 步）。

> 推荐 A1-a：不需要生成几十万字节的 JSON、每轮可独立截图归档、卡死恢复逻辑可集中一处。

### A2. 压测模式的入口
- **A2-a（推荐）**：Qt 平台新增“压测模式”开关/按钮（点击后弹窗选 exe + 次数 + 任务）。
- **A2-b**：命令行 Runner 新增参数（如 `--stress --exe ... --rounds 50`）。
- **A2-c**：两者都要。

### A3. 压测时“选哪个任务”的来源
- **A3-a（推荐）**：从任务库 `tasks/` 选一个已有 Task（单选）。
- **A3-b**：从当前主界面队列里选。
- **A3-c**：只针对“单个模式单次循环”做压测（像现在手工 JSON 那样，一轮只跑一个 preset）。

### A4. exe 路径的记忆与校验
- **A4-a（推荐）**：首次选择后记住到 `%LOCALAPPDATA%\Jens\压测模式\settings.json`
  （与后处理对比工具的任务配置保留策略一致），下次默认带出，可随时更换。
- **A4-b**：每次都要重新选。
- 校验：路径必须存在、必须是 `CrealityScan.exe`（名称含该关键字即可），可否接受？

## B. 执行流程与循环

### B1. “执行次数 N”的含义
- **B1-a（推荐）**：整个选中任务（含其全部模式/步骤）完整跑一遍 = 1 次，共跑 N 次。
- **B1-b**：每个模式各跑 N 次。

### B2. 每轮之间的“返回首页”
正常模式下，执行器在全部步骤通过后**自动补一次 `return_home`**（且约定任务 JSON 不内嵌
`return_home`，现有测试会校验这一点）。
- **B2-a（推荐）**：每轮循环体末尾由执行器自动执行返回首页（任务 JSON 仍不内嵌，
  与现有约定一致）。
- **B2-b**：任务 JSON 内每轮显式写 `return_home`（破坏现有约定，需同步改测试）。

### B3. 普通失败（非卡死）怎么处理
压测场景下遇到“步骤报错但软件没卡死”：
- **B3-a（推荐）**：记录本轮失败（截图+日志），**继续下一轮**，最后汇总通过率。
- **B3-b**：失败即停止，等人工处理（和现在正常模式一样）。
- **B3-c**：按现有 `on_fail` 策略（abort/continue/retry）各自生效，不额外改。

### B4. 一轮内有多模式时的失败范围
若一轮任务包含多个模式，某个模式失败：
- **B4-a（推荐）**：只该轮记为失败，继续该轮后续模式（视同 B3-a）。
- **B4-b**：该轮整体终止，直接进入下一轮。
- **B4-c**：其它。

## C. 卡死检测与恢复

### C1. “软件卡死”的判定标准
正常模式已有“带心跳的长等待轮询”。建议卡死定义为：
- **C1-a（推荐）**：单步执行超过**可配置超时**（如每步默认 300s），且等待期间
  “日志无新行推进”+“无心跳输出”才判定卡死（避免长扫描被误杀）。
- **C1-b**：仅凭单步超时即判定卡死。
- **C1-c**：窗口无响应（通过 win32 判断）即判定卡死。

### C2. 卡死恢复后的“重开”细节
- 强杀进程：用 `taskkill /F /IM CrealityScan.exe`（或按 PID），可否？
- **C2-a（推荐）**：重开 exe 前先等待进程完全退出（如等 2~5s），再启动新实例。
- **C2-b**：启动后等主窗口出现再继续。

### C3. 日志上报弹窗的处理
- **C3-a（推荐）**：提供弹窗截图模板，用模板匹配自动点击“确认/发送/关闭”按钮；
  匹配不到则截图留证并继续点击“关闭”类按钮。
- **C3-b**：需要你先提供该弹窗的截图与按钮文字，我来做模板。
- 请确认：弹窗按钮文字是什么？（如“发送”“取消”“关闭”“不发送”）

### C4. 恢复后从哪继续
- **C4-a（推荐）**：卡死那一轮**整轮重跑**（从该轮第一步重新开始）。
- **C4-b**：从卡死的那个**步骤**重试。
- **C4-c**：直接进入下一轮（本轮按失败计）。

### C5. 一轮内允许卡死恢复几次
- **C5-a（推荐）**：同一轮最多恢复 1~2 次，超过则本轮失败、进下一轮。
- **C5-b**：无限恢复。
- 请确认上限数值。

## D. 结果与产物

### D1. 每轮产物结构
- **D1-a（推荐）**：一个大 run_dir 下按 `round01/ round02/ …` 分轮归档
  （每轮独立 result.json + 截图 + 日志 + 轮次报告）。
- **D1-b**：每轮一个独立 run_dir（`artifacts/<任务名>_<时间戳>_r01/` 等）。

### D2. 汇总报告
压测结束是否要一份总报告？
- **D2-a（推荐）**：生成 `压测汇总.html` 或 `压测汇总.json`：总次数、通过/失败轮次、
  通过率、每轮耗时、失败轮次的截图/日志路径、卡死恢复记录。
- **D2-b**：不要汇总，只看每轮报告。

### D3. 是否通知
- **D3-a（推荐）**：沿用现有邮件通知，压测整体结束后按“全部通过 / 有失败”发一封汇总。
- **D3-b**：不通知。

### D4. 停止
压测 50+ 轮中途要能停止：
- **D4-a（推荐）**：复用现有“停止”按钮/F4，当前轮安全退出后不再启动下一轮。
- **D4-b**：其它。

## E. 其它

### E1. 与滑轨的关系
压测任务是否要联动滑轨（`slide_rail` 位置切换）？
- **E1-a（推荐）**：压测模式完全复用任务本身的配置（任务里有滑轨步骤就联动，没有就不动）。
- **E1-b**：压测模式默认不带滑轨。

### E2. 可配置参数
除 exe 路径和次数外，是否需要把这些做成弹窗可调：
- 每步超时（C1 用）
- 每轮最大卡死恢复次数（C5 用）
- 重开后等待窗口出现的时间
- **E2-a（推荐）**：全部给默认值，高级用户可在弹窗里改。
- **E2-b**：先全部固定默认值，后续再开放。

### E3. 压测模式是否进打包
- **E3-a（推荐）**：随主平台一起打包（`build.py` 自动带上）。
- **E3-b**：仅源码态使用。

### E4. 需要你额外提供
1. 日志上报弹窗的截图 + 按钮文字（C3 用）。
2. 你理想中“压测汇总报告”长什么样（可手绘/截图/文字描述）。
3. 现有 50 轮手工 JSON 是否作为压测模式的验收基准（对拍）。

### A. 形态与入口
| 项 | 决定 | 实现落点 |
|----|------|----------|
| A1 | **A1-a** | 执行器/调度层循环 N 轮，不做巨型展开 JSON |
| A2 | **A2-a** | Qt 主界面顶栏新增“压测模式”按钮 → 弹窗选任务/exe/次数 |
| A3 | **A3-a** | 从 `tasks/` 单选一个已有 Task |
| A4 | **A4-a** + 校验可接受 | exe 记忆到 `%LOCALAPPDATA%\Jens\压测模式\settings.json`；校验存在且文件名含 `CrealityScan` |

### B. 执行流程与循环
| 项 | 决定 | 实现落点 |
|----|------|----------|
| B1 | **B1-a** | 整任务完整跑一遍 = 1 轮 |
| B2 | **B2-a** | 轮次末尾由执行器自动 `return_home`，任务 JSON 不内嵌（保持现有测试约定） |
| B3 | **B3-a**（并**强杀软件进下一轮**） | 普通失败：记录本轮失败（截图+日志）→ 强杀 → 重开 → 下一轮 |
| B4 | **B4-b** | 一轮内某模式失败即该轮整体终止，进入下一轮 |

### C. 卡死检测与恢复
| 项 | 决定 | 实现落点 |
|----|------|----------|
| C1 | **C1-a** | 日志无新行 + 无心跳静默超过超时才判卡死（可配置） |

| C4 | **C4-c** | 卡死直接杀进程进入下一轮（本轮按失败计），不重跑 |
| C5 | **C5-a**，上限 **1** 次（只要卡死就杀进程进下一轮） | 每轮最多恢复 1 次，超过则本轮失败 |

### 压测汇总报告设计（D2）
- 文件：`压测汇总.json`（机器可读，供邮件/后续统计）+ `压测汇总.html`（人读）。
- 汇总字段：任务名、exe 路径、总轮次、开始/结束时间、总耗时、通过率、
  通过/失败/卡死/跳过计数、是否被停止、整体状态（passed/failed/stopped）。
- 每轮字段：轮次号、状态（passed/failed/frozen/skipped/stopped）、说明/原因、
  耗时、起止时间、轮次目录、轮次报告路径、错误信息。
- 统计口径：通过率 = 通过 /（通过+失败+卡死）× 100%（跳过与停止不计入分母）。
