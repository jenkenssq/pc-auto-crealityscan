# 安全、部署与运维设计

## 1. 安全目标

- 防止未登录访问；
- 防止普通用户越权修改共享任务；
- 防止一个账号控制其他用户 Agent；
- 防止篡改 Task JSON 和 Step 包；
- 防止任意文件读取和上传；
- 防止日志中的 HTML 或敏感内容破坏页面；
- 保证中心服务器和 Agent 可以恢复连接；
- 保持公司局域网部署简单可维护。

## 2. 权限矩阵

| 能力 | 管理员 | 普通用户 |
| --- | --- | --- |
| 管理用户 | 是 | 否 |
| 修改自己密码 | 是 | 是 |
| 查看共享任务 | 是 | 是 |
| 执行共享任务 | 是 | 是 |
| 复制共享任务 | 是 | 是 |
| 修改自己任务 | 是 | 是 |
| 修改他人任务 | 是 | 否 |
| 删除自己任务 | 是 | 是 |
| 删除他人任务 | 是 | 否 |
| 发布 Step | 是 | 否 |
| 查看自己的 Run | 是 | 是 |
| 查看全体 Run 摘要 | 是 | 否 |
| 查看普通用户原始日志内容 | 否 | 仅自己的 |
| 绑定自己的 Agent | 视管理员是否作为执行用户 | 是 |

管理员“不查看普通用户原始日志”必须落实到页面和 Artifact 下载授权，而不是仅隐藏菜单。

## 3. 用户认证

- 使用 Argon2id 保存密码哈希；
- 不记录明文密码；
- 登录错误不区分用户不存在和密码错误；
- 连续失败实施账号/IP 组合限速；
- Session Cookie 使用 `HttpOnly`、`SameSite=Lax/Strict`；
- 使用 HTTPS 时设置 `Secure`；
- 修改密码后吊销该用户其他 Web Session；
- 管理员重置密码记录审计事件；
- 禁用用户时吊销 Web Session 和 Agent 令牌。

## 4. Agent 身份安全

- 绑定码随机生成、短时有效、只使用一次；
- 服务器只保存绑定码哈希；
- 一个用户最多一个有效 Agent 令牌；
- Agent 令牌只展示一次；
- 数据库保存令牌哈希；
- Agent 使用 Windows 用户级安全存储保护令牌；
- 解绑、禁用用户或重新绑定时立即吊销旧令牌；
- Agent 只建立出站连接，不开放远程控制端口；
- Agent 每次 Run 校验 `run_id` 和绑定用户。

## 5. Task 与 Step 安全

### Task JSON

- 服务端校验结构和字段类型；
- Agent 执行前再次校验；
- 禁止 Task 指定任意 Python 模块或文件路径；
- 只允许引用已发布的 `step_id + version`；
- 参数设置大小和深度限制；
- 运行快照计算哈希并随任务下发。

### Step 包

- 只有管理员可发布；
- 每个版本不可变；
- manifest 记录全部文件 SHA-256；
- Agent 下载后校验再原子安装；
- 拒绝绝对路径、`..` 和链接逃逸；
- 限制包大小和文件数量；
- 记录发布者和发布时间；
- 后续可增加代码签名，但首版至少完成可信服务器传输和哈希校验。

## 6. 日志与 Artifact 安全

- 日志显示前进行 HTML 转义；
- 上传文件使用服务器生成的 Artifact ID；
- 服务器不信任 Agent 提交的目标路径；
- 文件保存在按用户和 Run 隔离的目录；
- 下载时根据数据库关系鉴权；
- 普通用户只能下载自己的 Artifact；
- 管理员 Run 摘要不包含普通用户原始 CrealityScan 日志下载链接；
- 对上传文件设置单文件和单 Run 大小上限；
- 校验上传完成后的大小与 SHA-256；
- Web 页面不得直接拼接磁盘绝对路径。

## 7. 网络地址设计

服务器 IP 可能变化，因此 Agent 和浏览器不能长期依赖写死的数字 IP。

推荐优先级：

1. 由公司 IT 配置内部 DNS，例如 `jens.company.local`；
2. 在 DHCP 中为服务器 MAC 地址保留固定地址，并同时提供稳定主机名；
3. 小规模验证阶段使用 Windows 主机名访问；
4. 最后才使用手工修改 Agent 配置的 IP 地址。

Agent 安装时保存服务器 URL，例如：

```text
https://jens.company.local
```

服务器 URL 必须可在 Agent 小窗口中查看和由用户手工修改，但修改后需要重新连接验证。不得把 IP 编译进 Agent。

## 8. HTTPS 与证书

虽然系统位于公司局域网，仍建议使用 HTTPS，原因包括：

- 保护用户密码；
- 保护 Agent 设备令牌；
- 防止 Task 和 Step 包在传输中被篡改；
- 保护可能包含设备信息的日志。

推荐使用公司内部 CA 证书。如果首版只能 HTTP 验证，应明确限定测试网络，并将 HTTPS 作为正式上线门禁。

Agent 不应提供“忽略所有证书错误”的长期配置。

## 9. 中心服务器部署

建议部署在可长期运行的公司 Windows 电脑或服务器：

```text
Reverse Proxy / HTTPS
FastAPI Web Service
Agent Gateway
SQLite WAL（首版）
Step Package Storage
Artifact Storage
Backup Directory
```

服务器不安装或运行用户的 CrealityScan 自动化任务。

首版用户量较小时可以使用 SQLite WAL，但必须满足：

- Web 服务只使用一个明确的数据库文件；
- 设置合理 busy timeout；
- 大段日志不写入数据库正文；
- 数据库与 Artifact 备份保持一致；
- 若并发和写入压力上升，迁移 PostgreSQL。

## 10. Agent 部署

- 使用安装包交付；
- 用户无需安装 Python；
- 用户双击 Agent 启动；
- 不要求开机自启；
- Agent 小窗口必须显示连接、绑定、环境和当前任务状态；
- Agent 更新不得在任务运行中替换文件；
- 更新失败时保留可运行旧版本并报告原因；
- Agent 退出前若 Runner 正在运行，必须警告用户。

## 11. 配置管理

中心配置：

- Session 有效期；
- Agent 心跳与离线阈值；
- Step 包和 Artifact 大小限制；
- Runner 温和停止宽限期；
- 每用户运行记录保留数，首版固定为20；
- 最低 Agent 版本；
- 存储目录和磁盘告警阈值。

Agent 本地配置：

- 服务器 URL；
- Agent 显示名称；
- 全局紧急停止快捷键是否启用；
- 快捷键组合；
- 本地运行和缓存目录。

敏感令牌不能进入普通 JSON 配置文件。

## 12. 监控与健康检查

中心服务健康指标：

- HTTP 服务状态；
- 数据库可读写；
- WebSocket 在线 Agent 数量；
- Run 状态分布；
- Artifact 存储剩余空间；
- Step 包存储完整性；
- 最近备份时间；
- 异常消息和上传失败数。

Agent 上报：

- 在线时间；
- Agent 版本；
- 当前状态；
- 当前 Run；
- 屏幕分辨率和缩放；
- CrealityScan 状态；
- 本地执行锁；
- 磁盘空间；
- 最后错误码。

管理员只看环境和状态摘要，不借此读取普通用户原始日志内容。

## 13. 备份与恢复

备份对象：

- 数据库；
- Step 发布包；
- 未超过保留期的服务器 Artifact；
- 系统配置；
- Agent 安装和升级包。

恢复演练必须验证：

- 用户与任务可恢复；
- Agent 旧令牌策略明确；
- Step 包哈希一致；
- Artifact 元数据与文件对应；
- 恢复后正在运行的 Run 不被误判为成功。

## 14. 每用户20条记录运维规则

- 只统计该用户已经进入终态的 Run；
- 按完成时间保留最近20条；
- 删除服务器数据库明细和服务器文件；
- 保留必要的审计墓碑时不得包含原始日志；
- 不删除 Agent 本地文件；
- 清理失败应重试并产生运维告警；
- 管理员不能通过手工修改数据库绕过一致性清理流程。

## 15. 审计要求

至少审计：

- 管理员用户操作；
- 用户登录和密码修改；
- Agent 绑定、解绑和令牌吊销；
- 任务创建、复制、修改和删除；
- Run 发起和本地紧急停止结果；
- Step 发布和状态变更；
- 自动保留清理；
- 服务器配置变化。
