# 实施计划与验收测试

## 1. 实施原则

- 先打通任务下发与本地执行，再开发完整任务编排页面；
- 先单用户单 Agent，验证稳定后再做多用户并行；
- 复用现有 Runner、Task JSON 和 Step，不先重写执行引擎；
- 每个阶段都必须可演示、可回退、可自动化验证；
- Web 与 Agent 的协议先定契约再写实现；
- Qt 在 Web 稳定前始终保留。

## 2. 阶段总览

| 阶段 | 目标 | 主要产出 |
| --- | --- | --- |
| 0 | 技术验证 | 单次任务从伪服务器下发到本地 Runner |
| 1 | 单用户闭环 | 登录、绑定、执行、进度、结果 |
| 2 | 网页任务编排 | 共享任务库、Step 组合、Task JSON |
| 3 | 多用户与发布 | 多 Agent 并行、权限、Step 包更新 |
| 4 | 正式部署 | HTTPS、备份、清理、升级和验收 |

## 3. 阶段0：技术验证

### 目标

验证最难且最关键的链路，不开发完整页面。

### 工作项

- 抽取与 Qt 无关的 Runner 启动接口；
- 为 `execute_case()` 设计兼容的结构化事件出口；
- 制作最小 Agent 原型；
- Agent 启动现有 Task JSON；
- 捕获 stdout/stderr；
- 将事件和日志发送给最小服务端；
- 验证浏览器关闭后任务继续；
- 验证 Agent 本地紧急停止；
- 验证 Qt 与 Agent 执行锁互斥。

### 门禁

- 不修改现有 Step 即可执行至少一个真实扫描任务；
- Runner 最终状态与现有报告一致；
- 结构化事件能准确反映每个 Step；
- 紧急停止不会被报告为成功；
- 原有 Qt 执行路径仍能运行。

## 4. 阶段1：单用户闭环

### 工作项

- FastAPI 项目骨架；
- 数据库迁移；
- 管理员创建普通用户；
- 登录、退出和修改密码；
- Agent 绑定码和设备令牌；
- Agent 心跳与状态页面；
- 查看现有任务；
- Run 创建与任务快照；
- WebSocket 任务下发；
- SSE 进度和日志；
- Artifact 上传和下载；
- 每用户最近20条基础清理。

### 门禁

- 普通用户从另一台电脑登录；
- 用户只能绑定一台 Agent；
- 网页点击执行后只在该用户 Agent 运行；
- 页面实时显示当前步骤；
- 浏览器刷新后恢复状态；
- 任务完成后可以查看报告和截图；
- Agent 离线时明确拒绝执行。

## 5. 阶段2：网页任务编排

### 工作项

- Step Registry Web API；
- Step 搜索和分类；
- Step 添加、移除和排序；
- preset 选择；
- 参数编辑与校验；
- 失败策略；
- 标准任务生成器；
- Task JSON 导入和导出；
- 任务复制；
- 所有权和乐观锁；
- 任务删除与运行快照兼容。

### 门禁

- 网页可复现当前 Qt 的主要任务编排能力；
- 导出的 Task JSON 能被现有 Runner 直接执行；
- 导入现有 Task JSON 后结构不丢失；
- 普通用户不能修改或删除他人任务；
- 复制他人任务后副本归当前用户；
- 管理员能管理全部任务。

## 6. 阶段3：多用户与 Step 发布

### 工作项

- 多 Agent WebSocket 连接；
- 多用户并行 Run；
- 单 Agent 并发锁；
- Step 包 manifest 和哈希；
- Agent 按需下载和缓存；
- Agent/Step 兼容版本；
- Agent 断线事件补传；
- Web 服务重启状态恢复；
- 管理员 Step 发布页面；
- 用户和 Artifact 隔离测试。

### 门禁

- 至少两台 Agent 同时运行不同任务且互不干扰；
- 同一 Agent 第二个任务被明确拒绝；
- 篡改 Step 包后 Agent 拒绝执行；
- Agent 断线重连后不重复 Step 记录；
- 用户无法访问他人的 Run 和 Artifact；
- 管理员不能通过普通页面读取用户原始日志。

## 7. 阶段4：正式部署

### 工作项

- 内部域名或稳定主机名；
- HTTPS 证书；
- Agent 安装包；
- Agent 升级与回退；
- 数据库和文件备份；
- 每用户20条完整清理；
- 存储和 Agent 状态监控；
- 审计日志；
- 管理员操作手册；
- 用户安装和使用说明；
- 灾难恢复演练。

### 门禁

- Agent 配置不写死 IP；
- 服务器重启后用户、任务和历史记录完整；
- HTTPS 下账号和 Agent 正常工作；
- 第21条终态记录产生后最旧服务器记录和文件被清理；
- Agent 本地文件未被服务器清理；
- 更新失败可以继续使用旧 Agent；
- 备份可以恢复到验证环境。

## 8. 测试分层

### 8.1 单元测试

- 密码哈希与验证；
- 权限判断；
- Task JSON 校验；
- Task 所有权；
- Run 状态机；
- 每用户20条清理；
- 消息幂等；
- Step manifest 和哈希；
- 路径安全；
- 快捷键配置校验。

### 8.2 API 集成测试

- 登录、退出和禁用用户；
- 普通用户越权修改他人任务返回403；
- 复制共享任务产生新所有者；
- Agent 一对一绑定唯一约束；
- Agent 忙碌、离线和环境异常；
- Artifact 上传与下载鉴权；
- 管理员日志访问限制；
- Run 第21条触发清理。

### 8.3 协议测试

- Agent hello 和版本协商；
- 心跳超时和恢复；
- `run_offer` 接受与拒绝；
- 重复 `message_id`；
- 重复和乱序 `seq`；
- Agent 断线补传；
- 日志偏移续传；
- 大文件上传中断续传；
- 不兼容协议版本。

### 8.4 Agent 本地测试

- 未绑定状态；
- 绑定码过期和重复使用；
- CrealityScan 未启动；
- 窗口找不到；
- 分辨率或缩放不符；
- 本地执行锁被 Qt 占用；
- Runner 正常完成和异常退出；
- 紧急停止按钮；
- 全局快捷键默认关闭；
- 快捷键冲突；
- Agent 退出时 Runner 正在运行。

### 8.5 端到端测试

- 用户创建任务并在自己的 Agent 执行；
- 用户执行他人共享任务；
- 用户复制他人任务后编辑副本；
- 两位用户同时执行；
- 浏览器执行期间关闭再打开；
- Agent 执行期间短暂断网；
- Web 服务执行期间重启；
- 失败 Step 截图、错误和报告展示；
- 本地紧急停止后的状态和产物；
- Qt 与 Agent 互斥。

## 9. 用户验收场景

### UAT-01 新用户首次使用

管理员创建账号，用户登录、修改密码、下载并启动 Agent、输入绑定码，页面显示在线空闲。

### UAT-02 执行共享任务

用户选择其他人创建的任务并执行，任务在自己的 Agent 和 CrealityScan 上运行，创建者电脑不受影响。

### UAT-03 创建自定义任务

用户任意组合已发布 Step、选择 preset、保存任务；其他用户可以看到、执行和复制，但不能修改原任务。

### UAT-04 多用户并行

两位用户同时执行不同任务，各自页面只显示自己的 Run 和日志，两台 Agent 均正常运行。

### UAT-05 本地紧急停止

用户在 Agent 小窗口确认紧急停止，Runner 结束，网页最终显示“本地停止”，已有日志和产物可查看。

### UAT-06 保留策略

同一用户产生第21条终态记录后，网页只显示最近20条；最旧服务器产物已删除，Agent 本地原文件不受影响。

## 10. 完成定义

一个阶段只有同时满足以下条件才算完成：

- 代码评审完成；
- 自动化测试通过；
- 对应文档同步更新；
- 安全与权限测试通过；
- 没有破坏 Qt 和现有 Runner；
- 在真实 CrealityScan 环境完成验收；
- 已记录已知限制和回退方法。
