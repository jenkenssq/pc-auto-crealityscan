# 需求规格说明

## 1. 背景

当前 Jens 工具要求把完整项目移动到用户电脑，并在本地启动 Qt 页面后使用。这会带来分发体积大、版本难统一、任务资产分散、维护成本高等问题。

改造后，项目管理能力集中到 Web 平台；用户本地只安装执行所必需的 Agent。用户使用浏览器完成日常操作，Agent 在本地桌面执行 Airtest。

## 2. 用户角色

### 2.1 管理员

管理员只有一个，负责：

- 用户账号增删改查；
- 重置用户密码和禁用账号；
- 管理全部共享任务；
- 发布、启用和停用 Step 版本；
- 维护 Agent 安装包和升级包；
- 查看用户、Agent 在线状态和任务结果状态；
- 维护服务器地址、存储和系统配置；
- 查看审计记录。

管理员不需要读取普通用户上传的原始 CrealityScan 日志内容。

### 2.2 普通用户

普通用户可以：

- 登录和修改自己的密码；
- 绑定一台属于自己的 Agent；
- 查看全部共享任务；
- 执行任意共享任务；
- 复制任意共享任务，副本归自己所有；
- 创建任务并任意组合已发布 Step；
- 修改、删除自己创建的任务；
- 查看自己的 Agent 状态；
- 查看自己的当前任务、进度、日志和最近20条执行记录；
- 下载自己的报告、截图和原始日志。

普通用户不能：

- 修改或删除其他用户创建的任务；
- 查看其他用户的运行记录和产物；
- 上传或修改 Python Step；
- 管理用户和 Agent 版本；
- 从网页停止正在运行的任务。

## 3. 功能需求

### FR-001 登录认证

- 系统必须要求用户名和密码登录；
- 管理员创建普通用户初始账号；
- 用户首次登录不强制改密，但页面应提供修改密码入口；
- 被禁用账号不能登录；
- 用户只能修改自己的密码。

### FR-002 Agent 绑定

- 一个账号最多绑定一台有效 Agent；
- Agent 首次启动应显示短时有效绑定码；
- 用户在网页输入绑定码完成绑定；
- 新绑定必须明确处理已有绑定，不能静默绑定第二台；
- 页面应显示 Agent 在线、离线、空闲、运行中和异常状态。

### FR-003 共享任务库

- 所有已登录用户均可查看共享任务；
- 所有用户均可执行和复制共享任务；
- 任务必须记录创建人；
- 普通用户只能修改、删除自己创建的任务；
- 管理员可以修改、删除全部任务；
- 复制任务会创建新的任务 ID，所有者为复制者；
- 删除任务不能破坏已有运行快照。

### FR-004 网页任务编排

- 显示所有管理员已发布且启用的 Step；
- 支持搜索 Step；
- 支持添加、移除和排序 Step；
- 支持修改 Step 显示名称；
- 支持编辑 Step 参数；
- 有 `presets.json` 时提供 preset 选择；
- 支持 `abort`、`continue` 和 `retry` 失败策略；
- 支持现有标准任务生成器；
- 支持 Task JSON 导入和导出；
- 保存前必须校验 `step_id + version`、参数结构和至少一个 Step。

### FR-005 任务执行

- 用户只能把任务下发到自己的已绑定 Agent；
- Agent 离线、忙碌或环境异常时拒绝启动并说明原因；
- 每次运行保存不可变 Task JSON 快照；
- 单台 Agent 同一时间只能接受一个任务；
- 不同 Agent 可以并行运行；
- 浏览器关闭或刷新不能中断任务；
- 网页不提供运行中停止和暂停恢复。

### FR-006 本地紧急停止

- Agent 小窗口必须提供清晰的“紧急停止”按钮；
- 只有 Agent 正在执行时按钮可用；
- 点击后必须二次确认，避免误触；
- Agent 应先尝试温和终止 Runner，超时后再强制结束；
- 停止结果上报为 `stopped_local`，不能标记为成功；
- Agent 提供可配置全局快捷键；
- 全局快捷键默认关闭；
- 启用或修改快捷键时检查冲突并提示用户；
- 快捷键触发后仍需在 Agent 本地给出明确反馈。

### FR-007 实时进度和日志

- 页面显示任务总步骤数、当前步骤、完成数和最终状态；
- 显示每一步的状态、尝试次数、耗时和错误摘要；
- 实时展示 Runner 标准输出和标准错误；
- 普通日志不能作为步骤完成判据；
- 浏览器断线重连后可恢复历史进度和日志；
- Agent 短暂断线后应补传未确认事件。

### FR-008 运行记录和产物

- 每位用户在服务器只保留最近20条运行记录；
- 新记录完成后自动清理该用户最旧的超额记录；
- 清理服务器记录时同步删除其服务器端产物；
- 不尝试删除 Agent 本地产物；
- 用户只能查看和下载自己的产物；
- 管理员可以查看运行状态与摘要，但不提供查看普通用户原始 CrealityScan 日志内容的入口。

### FR-009 Step 发布

- 只有管理员可以发布 Step 包；
- Step 包必须包含版本和文件哈希；
- Agent 只执行服务器发布且校验通过的 Step；
- 新版本不得覆盖已经被运行快照引用的旧版本；
- Agent 按任务需要下载缺失资源并进行本地缓存。

### FR-010 Qt 兼容

- 现有 Qt 平台继续可用；
- Qt、Agent 和手动 Runner 使用同一个跨进程执行锁；
- 任一入口执行时，其他入口不得再次操作 CrealityScan；
- Web 改造不能破坏现有 Task JSON 和 Step 加载规则。

## 4. 非功能需求

### NFR-001 可用性

- 中心服务器应支持长期运行；
- Agent 断线后自动重连；
- Web 服务重启后能够根据 Agent 上报恢复状态；
- 浏览器刷新不丢失已落盘信息。

### NFR-002 性能

- 普通页面操作目标响应时间不超过2秒；
- Agent 状态变化目标展示延迟不超过5秒；
- 实时日志目标端到端延迟不超过2秒；
- 单个日志窗口必须限制浏览器内存中的最大行数。

### NFR-003 安全

- 密码不得明文保存；
- 普通用户数据必须按用户隔离；
- Agent 不开放局域网入站控制端口；
- 任务和 Step 包必须在服务器与 Agent 双端校验；
- 所有下载必须通过受控资源 ID，禁止任意路径读取。

### NFR-004 兼容性

- 保持现有 Task JSON 格式兼容；
- 保持 `step_id + version` 动态加载约定；
- 保持源码态和 PyInstaller 安装态可运行；
- Agent 运行环境必须满足现有 CrealityScan、分辨率和缩放要求。

### NFR-005 可维护性

- Web、Agent、执行引擎和 Step 发布职责分离；
- 结构化事件协议必须版本化；
- Agent 与 Step 包版本独立；
- 关键行为应有审计记录和可自动化测试的契约。

## 5. 关键业务规则

| 编号 | 规则 |
| --- | --- |
| BR-001 | 一个账号最多绑定一台有效 Agent |
| BR-002 | 每台 Agent 同时最多运行一个任务 |
| BR-003 | 多台 Agent 可以并行运行 |
| BR-004 | 共享任务所有人可查看、执行和复制 |
| BR-005 | 普通用户只能修改、删除自己创建的任务 |
| BR-006 | 运行使用不可变任务与 Step 版本快照 |
| BR-007 | 每用户服务器端只保留最近20条运行记录 |
| BR-008 | 服务器清理不影响 Agent 本地文件 |
| BR-009 | 网页不提供停止和暂停，紧急停止仅在 Agent 本地执行 |
| BR-010 | 普通用户不能上传可执行 Step 代码 |
