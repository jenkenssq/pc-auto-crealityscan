# 迁移、兼容与风险清单

## 1. 迁移目标

在保留现有自动化资产和 Qt 应急能力的同时，引入 Web 控制面和本地 Agent。迁移过程不能要求一次性重写全部 Step，也不能让现有任务格式失效。

## 2. 现有模块复用映射

| 现有模块 | 后续定位 | 改造原则 |
| --- | --- | --- |
| `jens_platform/case_store.py` | Web 与 Qt 共享 Task 模型 | 抽成无 Qt 依赖的应用服务 |
| `jens_platform/task_generator.py` | Web 标准任务生成器 | 保留配置驱动，新增 API 适配 |
| `jens_platform/step_registry.py` | Step 元数据来源 | 增加发布包和启用状态，不改变 ID 规则 |
| `jens_platform/runner.py` | Qt 子进程适配器参考 | 抽取通用 Runner Supervisor，Qt/Agent 分别适配 |
| `jens_platform/main.py` | 保留 Qt UI | 不继续加入 Web 或 Agent 业务逻辑 |
| `engine/executor.py` | 共享执行核心 | 增加可选事件回调，保持原调用兼容 |
| `jens_runner_entry.py` | Agent 本地 Runner 入口 | 保留 Task JSON 执行与 Artifact 生成 |
| `engine/report_html.py` | 报告生成 | 保持现有输出，Web 仅托管和下载 |
| `steps/` | Step 源资产 | 构建为版本化可信发布包 |
| `tasks/` | 初始共享任务来源 | 导入数据库，继续支持 JSON 导出 |
| `artifacts/` | Agent 本地产物格式 | Agent 上传选定文件，服务器独立保留20条 |

## 3. 推荐代码边界（后续实现参考）

本阶段不创建代码，后续实现建议按职责拆分：

```text
jens_core/             无 UI 的 Task、Step、Run 领域模型
jens_web/              FastAPI、页面、认证、数据库和 SSE
jens_agent/            Agent 小窗口、通信、更新和 Runner 监督
jens_protocol/         浏览器/Agent 共用消息契约
engine/                现有执行引擎
jens_platform/         保留 Qt 页面和 Qt 适配
steps/                 Step 开发源
```

不要让 `jens_web` import PyQt，也不要让 `jens_agent` 依赖 Web 页面模块。

## 4. 兼容策略

### 4.1 Task JSON

- 继续支持现有字段；
- Web 数据库保存 JSON 定义；
- 导入后不得丢失未知但合法字段；
- 执行时导出不可变 JSON 快照；
- `run_options` 等运行期字段应与任务定义字段区分；
- 对格式升级增加显式 schema 版本，不通过猜测迁移。

### 4.2 Step

- 保留 `step_id + version` 动态加载规则；
- 保留 `step.json`、`impl.py`、`presets.json` 和 `templates/` 结构；
- Step 源码仍在当前项目维护；
- 发布流程将版本目录打成不可变包；
- 旧 Run 继续引用旧 Step 版本；
- 普通用户只组合 Step，不编辑 Step 代码。

### 4.3 Qt

- Qt 继续读取现有 Task JSON；
- Qt 仍可用于本机运行和维护；
- Qt 与 Agent 共用执行锁；
- 新的核心服务优先无 Qt 依赖；
- Web 完成后不立即删除 Qt 功能。

### 4.4 安装态

- Agent 采用独立 PyInstaller 配置；
- 不直接把完整 Qt 安装包改名为 Agent；
- Agent 包含执行必需依赖，不包含开发文档和完整任务库；
- Step 包与 Agent 基础程序分离更新；
- 保持中文路径和 Windows 本地编码兼容测试。

## 5. 数据迁移

初次上线建议：

1. 创建管理员账号；
2. 扫描现有 `steps/`，建立 Step 发布基线；
3. 为每个版本生成 manifest 和哈希；
4. 将现有 `tasks/*.json` 导入共享任务库；
5. 给导入任务设置管理员为初始所有者；
6. 保留原文件作为只读迁移备份；
7. 不迁移历史本地 artifacts，避免混淆用户归属；
8. 选择一个用户和一台 Agent 进行灰度验证。

## 6. 发布与回退

### Web 服务

- 数据库变更使用可回退迁移；
- 发布前备份数据库和 Step 包仓库；
- 新版本先在验证环境连接测试 Agent；
- Web 回退不能让协议版本倒退到无法识别现有 Agent。

### Agent

- 任务运行期间不升级；
- 下载新版本后先校验；
- 更新失败保留旧版本；
- Agent 与协议版本不兼容时拒绝新任务但仍能显示错误；
- 不在升级过程中清理本地 artifacts。

### Step 包

- 同一版本不可覆盖；
- 有问题的版本只停用，不修改历史内容；
- 新任务不能选择停用版本；
- 已冻结 Run 仍可验证其资源清单。

## 7. 风险清单

| ID | 风险 | 影响 | 概率 | 应对措施 |
| --- | --- | --- | --- | --- |
| R-01 | 用户锁屏或切换会话 | Airtest 无法操作桌面 | 高 | Agent 运行前检查并在页面明确提示 |
| R-02 | 用户在执行时操作鼠标键盘 | 点击位置被干扰 | 高 | Agent 显示运行状态，文档要求运行期间勿操作 |
| R-03 | 服务器 IP 变化 | Agent 和浏览器无法连接 | 中 | 内部 DNS、DHCP 保留地址或稳定主机名 |
| R-04 | Agent 断线 | 页面状态延迟、日志未上传 | 中 | 本地持久化队列、序号补传和心跳 |
| R-05 | Web 服务重启 | Run 状态暂时未知 | 中 | Agent 重连上报、事件幂等、禁止猜测成功 |
| R-06 | 多入口同时运行 | Qt/Agent 相互点击干扰 | 高 | 跨进程执行锁和陈旧锁恢复 |
| R-07 | Step 包被篡改 | 执行未知代码或模板 | 低/高影响 | 管理员发布、HTTPS、SHA-256 和不可变版本 |
| R-08 | 普通用户越权编辑任务 | 共享资产被破坏 | 中 | 服务端所有权鉴权和集成测试 |
| R-09 | 用户越权读取日志 | 数据泄露 | 中 | Artifact 按 Run/user 鉴权，管理员原始日志限制 |
| R-10 | 本地磁盘持续增长 | Agent 无法继续运行 | 高 | 执行前磁盘检查和本地清理提示 |
| R-11 | 服务器 Artifact 增长 | 服务不可用 | 低 | 每用户最近20条自动清理和磁盘告警 |
| R-12 | 紧急停止后设备状态残留 | 后续任务失败 | 中 | 状态标记、本地提示、下次运行前环境检查 |
| R-13 | 全局快捷键冲突或误触 | 任务意外停止 | 中 | 默认关闭、冲突检查、二次确认/反馈 |
| R-14 | stdout 编码不一致 | 中文日志乱码 | 中 | 延续 Windows `mbcs` 兼容并统一上传 UTF-8 |
| R-15 | 结构化事件与最终报告不一致 | 页面状态错误 | 中 | 以 Runner 终态和结果校验，增加契约测试 |
| R-16 | SQLite 写竞争 | 请求失败或延迟 | 低到中 | WAL、busy timeout、日志文件化，必要时迁移 PostgreSQL |

## 8. 需要重点验证的技术假设

- Agent 在普通用户交互会话中能稳定调用现有 Runner；
- 结构化事件不会改变现有 Step 行为；
- WebSocket 断线时本地任务可以完全独立运行；
- Agent 能可靠区分 Qt、手动 Runner 和自己的执行锁；
- Step 按需缓存不破坏 Python 动态 import；
- PyInstaller Agent 能包含 Airtest、OCR 和相关 DLL；
- 原始 CrealityScan 日志可以按 Run 准确归档；
- 公司网络允许浏览器和 Agent 访问稳定主机名；
- 多台 Agent 同时上传日志不会造成中心服务阻塞。

## 9. 上线前禁止项

存在以下任一情况不得正式上线：

- 密码或 Agent 令牌明文存储；
- Agent 执行未校验 Step 包；
- 普通用户能修改他人任务；
- 用户能下载他人 Artifact；
- 管理员页面暴露普通用户原始 CrealityScan 日志；
- 同一 Agent 能启动两个 Runner；
- Qt 与 Agent 没有互斥锁；
- 浏览器断开导致 Runner 被终止；
- 本地紧急停止被记录为成功；
- 服务器地址写死为可能变化的 IP；
- 第21条记录不能触发一致的服务器清理；
- Web 改造导致现有 Task JSON 无法由 Runner 执行。

## 10. 最终迁移判定

当以下条件持续满足后，普通用户日常操作可以从 Qt 迁移到 Web：

- Web 编排覆盖现有主要 Qt 功能；
- Agent 真实扫描任务稳定通过；
- 多用户并行运行验证完成；
- 权限和日志隔离测试通过；
- Agent 更新和回退验证完成；
- Web/Agent 断线恢复验证完成；
- 管理员和普通用户完成验收；
- Qt 仍可作为本机应急入口。
