# 总体架构设计

## 1. 架构目标

将现有本地 Qt 单体使用方式拆成集中控制面和分布式执行面，在不改变 Airtest 必须操作本地桌面的前提下，实现统一账号、共享任务、集中维护和多用户并行执行。

## 2. 总体结构

```text
                              公司局域网

┌───────────────────────────────────────────────────────────────┐
│                       中心 Web 平台                           │
│  Web UI / Auth / Task Library / Step Registry / Run Service   │
│  Agent Gateway / Event Service / Artifact Service / Database  │
└───────────────┬─────────────────────┬─────────────────────────┘
                │                     │
           HTTP + SSE            WebSocket + HTTPS
                │                     │
       ┌────────▼────────┐   ┌────────▼──────────────────────┐
       │ 用户浏览器       │   │ 用户本地 Jens Agent          │
       │ 创建/执行/查看   │   │ 绑定/心跳/更新/本地执行/上传  │
       └─────────────────┘   └────────┬──────────────────────┘
                                      │ 子进程 + 本地执行锁
                             ┌────────▼──────────────────────┐
                             │ 现有 Jens Runner              │
                             │ execute_case / Airtest / Step │
                             └────────┬──────────────────────┘
                                      ▼
                             CrealityScan + 扫描设备
```

## 3. 组件职责

### 3.1 Web UI

- 登录和修改密码；
- 共享任务库；
- Step 编排和参数配置；
- Agent 绑定和状态展示；
- 发起本机任务；
- 查看当前步骤、实时日志和最近20条记录；
- 查看和下载自己的运行产物；
- 管理员维护用户、任务和 Step 发布包。

Web UI 不直接连接用户电脑，也不直接调用 Airtest。

### 3.2 Auth Service

- 用户认证；
- 管理员和普通用户授权；
- Session 生命周期；
- 用户密码修改；
- Agent 设备令牌签发和吊销；
- 登录与敏感操作审计。

### 3.3 Task Service

- 保存共享 Task JSON；
- 执行任务所有权规则；
- 提供复制、导入和导出；
- 校验 Step 版本和参数；
- 创建不可变运行快照。

### 3.4 Step Registry 与 Package Service

- 扫描和展示 Step 元数据；
- 保存管理员发布的 Step 版本；
- 生成资源清单与 SHA-256；
- 向 Agent 提供按需下载；
- 维护 Agent 最低兼容版本。

### 3.5 Agent Gateway

- 接受 Agent 主动建立的 WebSocket 长连接；
- 校验 Agent 令牌；
- 接收心跳和环境状态；
- 将 Run 下发到正确用户的 Agent；
- 接收日志、结构化事件和最终结果；
- 处理断线、重连和消息去重。

### 3.6 Run Service

- 校验用户与 Agent 绑定关系；
- 校验 Agent 在线、空闲和环境状态；
- 创建 Run 和资源清单；
- 跟踪状态机；
- 将事件推送给浏览器；
- 执行每用户最近20条保留策略。

### 3.7 Jens Agent

- 展示本地状态和绑定码；
- 保持服务器连接和心跳；
- 下载、校验和缓存 Step 包；
- 创建本地 Task JSON 快照；
- 获取本地执行锁；
- 启动和监督 Runner 子进程；
- 缓冲并上传日志和事件；
- 上传报告与截图；
- 提供本地紧急停止按钮和可选全局快捷键。

### 3.8 现有 Runner 与执行引擎

- 解析 Task JSON；
- 初始化 Airtest；
- 动态加载 Step；
- 操作 CrealityScan；
- 执行失败策略；
- 生成结果、截图和报告。

执行引擎需要增加结构化事件出口，但现有调用方式必须保持兼容。

## 4. 部署拓扑

### 4.1 中心服务器

```text
FastAPI
数据库
Web 静态资源与模板
Step 发布包仓库
服务器端运行记录与产物
Agent 安装与升级包
```

服务器不需要安装 CrealityScan，也不执行用户的 Airtest 任务。

### 4.2 用户电脑

```text
Jens Agent
Airtest 运行时
Jens Runner / engine
按需下载的 Step 缓存
本地日志和 artifacts
CrealityScan
扫描仪及驱动
```

Agent 必须运行在登录用户的交互会话中，不作为 Session 0 Windows Service 执行。

## 5. 关键执行链路

### 5.1 Agent 绑定

```text
Agent 生成绑定码
    → 用户登录网页输入绑定码
    → 服务器校验绑定码和账号现有绑定
    → 服务器签发设备令牌
    → Agent 保存令牌并重新认证
    → 网页显示 Agent 在线状态
```

### 5.2 创建任务

```text
用户选择 Step
    → 配置 preset/params/on_fail
    → 服务端校验 Step 版本
    → 保存共享任务并记录创建人
    → 所有用户可以查看、执行和复制
```

### 5.3 执行任务

```text
用户点击执行
    → Run Service 校验任务、用户和 Agent
    → 冻结 Task JSON 和 Step 资源清单
    → Agent 接收并确认任务
    → Agent 下载缺失资源并校验哈希
    → Agent 获取本地执行锁
    → Agent 启动 Runner
    → Runner 按步骤执行
    → Agent 上传日志和事件
    → 浏览器通过 SSE 实时显示
    → Agent 上传最终产物
    → Run 完成并触发20条保留清理
```

### 5.4 本地紧急停止

```text
用户点击 Agent 紧急停止或触发已启用快捷键
    → Agent 二次确认或显示明确触发反馈
    → terminate Runner
    → 宽限期后仍未退出则 kill
    → 释放本地执行锁
    → 记录 stopped_local
    → 向服务器补传最终状态和已有产物
```

## 6. 并发模型

并发规则：

```text
Agent 内并发数 = 1
平台总并发数 = 在线且空闲的 Agent 数量
```

服务器不维护全局单任务队列。每个用户任务直接路由到该用户唯一绑定的 Agent：

- Agent 空闲：允许启动；
- Agent 运行中：拒绝再次启动，不在服务器排队；
- Agent 离线：拒绝启动；
- Agent 环境异常：拒绝启动并返回原因。

首版采用“忙碌即拒绝”比隐式排队更清晰，避免用户忘记已经提交的任务。未来如增加每 Agent 队列，需要单独变更需求。

## 7. 状态一致性

### 7.1 权威来源

| 状态 | 权威来源 |
| --- | --- |
| 用户和任务定义 | 中心数据库 |
| Agent 在线状态 | Agent 最近心跳 |
| 本地进程是否运行 | Agent |
| 步骤执行状态 | Runner 结构化事件，经 Agent 上报 |
| 最终报告 | Agent 本地产物上传结果 |

### 7.2 故障恢复原则

- 浏览器不是执行状态权威；
- WebSocket 断开不立即判定任务失败；
- 所有 Agent 事件使用单调递增 `seq`；
- 服务器按 `run_id + seq` 幂等保存；
- Agent 保存最后已确认序号，重连后补传；
- Web 服务重启后等待 Agent 重连并校正运行状态；
- Agent 进程意外退出且 Runner 状态未知时，Run 标记为 `interrupted`，不能猜测成功。

## 8. 数据与文件边界

### 中心服务器保存

- 用户、角色和 Agent 绑定；
- 共享任务和所有权；
- 每用户最近20条 Run；
- Run 结构化事件和步骤结果；
- 与保留 Run 对应的服务器产物；
- Step 发布包；
- 审计记录。

### Agent 本地保存

- 设备令牌；
- Agent 设置和快捷键；
- Step 缓存；
- 本地 Task 快照；
- 本地完整日志和 artifacts；
- 未上传或未确认的事件缓冲。

服务器清理历史记录时不向 Agent 发送本地删除命令。

## 9. 架构质量属性

- 隔离：一个用户 Agent 故障不影响其他用户执行；
- 兼容：现有 Task JSON 和 Runner 保持可用；
- 可恢复：浏览器、Agent 和服务器均允许短暂断线；
- 可追溯：每次运行冻结任务和 Step 版本；
- 可更新：Agent 运行时与 Step 包分开发布；
- 最小权限：普通用户只能管理自己的任务，不能发布代码；
- 可维护：Web 页面、调度、通信和执行引擎不互相侵入。
