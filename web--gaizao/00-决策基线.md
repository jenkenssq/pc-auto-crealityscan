# 决策基线

## 1. 产品定位

Jens Web 平台是现有 PC 自动化测试工具的集中控制面。用户通过公司局域网浏览器创建和执行任务，本地 Agent 负责实际操作 CrealityScan。

本项目不是云端代替用户电脑执行桌面自动化，也不是把完整项目目录通过网页下载给用户。

## 2. 已确认决策

### 2.1 部署与执行

- Web 服务只部署在一台中心服务器电脑；
- 每位普通用户拥有独立 Windows 电脑、CrealityScan 和扫描设备；
- 每位用户电脑只需安装精简 Agent；
- Airtest 必须在用户登录且未锁屏的本地交互桌面执行；
- 每台 Agent 同时只执行一个任务；
- 不同用户的 Agent 可以并行执行；
- Agent 由用户双击启动，不要求开机自启或托盘常驻；
- 一个账号只绑定一台 Agent；
- 账号由管理员增删改查，普通用户可以修改自己的密码。

### 2.2 任务与 Step

- Task JSON 继续作为标准导入、导出和运行快照格式；
- 网页开放当前项目已有的任务编排功能；
- 普通用户可以任意组合管理员已经发布的 Step；
- 普通用户不能上传或修改 Python Step 代码；
- 任务库对所有用户共享；
- 所有用户可以查看、执行和复制共享任务；
- 普通用户只能修改、删除自己创建的任务；
- 管理员可以管理全部任务。

### 2.3 运行控制与记录

- 网页不提供远程停止正在运行任务的能力；
- 不支持暂停后继续；
- Agent 小窗口必须提供本地“紧急停止”按钮；
- Agent 可配置全局紧急停止快捷键；
- 全局快捷键默认关闭，避免与 CrealityScan 或其他软件冲突；
- Web 服务器仅保留每位用户最近20条执行记录；
- 超出20条时删除服务器记录和服务器产物；
- 服务器清理不删除用户电脑上的本地日志和产物；
- 普通用户可以查看和下载自己的原始 CrealityScan 日志；
- 管理员不需要查看普通用户原始 CrealityScan 日志内容。

### 2.4 网络与兼容

- 系统仅供公司局域网访问；
- 中心服务器可以长期运行，但 IP 可能变化；
- Agent 和浏览器不应写死服务器 IP，应优先使用稳定主机名或内部域名；
- 现有 Qt 平台继续保留，用于开发、维护和应急；
- Qt、Agent 和手动 Runner 必须共享本地执行锁。

## 3. 术语

| 术语 | 定义 |
| --- | --- |
| Web 平台 | 中心部署的登录、任务、运行状态和管理系统 |
| Agent | 用户电脑上的精简执行程序 |
| Runner | 当前项目中负责运行 Task JSON 的执行入口 |
| Step | 一个可复用的自动化步骤及其元数据、实现和模板 |
| Task | 按顺序组合的 Step 集合，兼容现有 Task JSON |
| Run | 用户对某一 Task 快照发起的一次执行 |
| Artifact | 日志、截图、结果 JSON、报告等运行产物 |
| Step 包 | 由管理员发布、供 Agent 下载的可信 Step 版本 |

## 4. 首版范围

首版必须完成：

- 管理员和普通用户登录；
- 用户管理及用户自行修改密码；
- 一个账号绑定一个 Agent；
- Agent 在线状态和环境检查；
- 共享任务库及已确认的所有权规则；
- 网页任务编排和 Task JSON 导入、导出；
- 任务下发到当前用户 Agent；
- 多 Agent 并行、单 Agent 串行；
- 当前步骤、执行进度和实时日志；
- 运行结果和产物查看；
- 每用户最近20条服务器运行记录；
- Agent 本地紧急停止按钮；
- Qt 与 Agent 执行互斥。

## 5. 明确不在首版范围

- 一个账号绑定多台 Agent；
- 网页远程停止；
- 暂停后继续；
- 普通用户上传 Step 代码；
- 互联网访问；
- 自动删除用户电脑本地产物；
- 停用 Qt 平台；
- 跨公司网络或公网执行；
- 服务器远程控制用户鼠标和键盘。
